# Monarch: dated public behavior

Public documentation inspected 2026-09-27. This is a task-specific adapter reference, not proof of current household settings or a live compatibility test. Recheck the relevant official page when behavior changes or is uncertain, following [capabilities](capabilities.md). Record private observations separately. Older `help.monarchmoney.com` search results can describe earlier behavior; open the current official article rather than relying on snippets.

| Operation and documented source | Decision-relevant behavior |
|---|---|
| [Manual transactions](https://help.monarch.com/hc/en-us/articles/360058441811-Creating-Manual-Transactions), updated 2026-03-16 | Manual additions are supported on synced accounts without changing their balances. A later matching synced row does not automatically remove the manual row. On manual accounts, choose the balance-adjustment option explicitly. Preserve a repair-watch case and recheck later feed arrival. |
| [Transaction import](https://help.monarch.com/hc/en-us/articles/4409682789908-Importing-Transactions-Manually), updated 2026-08-14 | Web importer supports ID-based updates for Monarch-exported rows; CSV priority replaces existing rows in the CSV's date interval; Monarch priority keeps existing data and may skip rows; import-all can duplicate. Synced balances stay unchanged; manual-account balance choice matters. Imports cannot simply be undone. Record exact mode, scope and observed completion. |
| [Native splits](https://help.monarch.com/hc/en-us/articles/360050178492-Splitting-Transactions), updated 2026-07-28 | Each split is managed as a transaction. Manual splitting removes Needs Review by default. Inspect source-parent/child IDs, totals and review state; account for those effects in authorization and verification. Unsplit is different from deleting the underlying purchase. |
| [Transaction review](https://help.monarch.com/hc/en-us/articles/5528707082516-Reviewing-Transactions), updated 2026-07-28 | Review status can be changed per row or in bulk; a transaction may be assigned for review by anyone, oneself or a household member. Category review and statement reconciliation are distinct. |
| [Receipt imports](https://help.monarch.com/hc/en-us/articles/44244210547860-Importing-Receipts-into-Monarch), updated 2026-09-21 | Native receipt import matches posted transactions and can add notes/tags/attachments and automatic splits. A receipt arriving before posting can match later. Avoid creating a new transaction while expecting that feed row. Refund line items are not extracted; use source/context for returns. Check existing imported receipts before seeking mailbox evidence. |
| [Recurring expenses and bills](https://help.monarch.com/hc/en-us/articles/4890751141908-Tracking-Recurring-Expenses-and-Bills), updated 2026-06-29 | Supports detection and manual review of recurring merchants. One recurring transaction per merchant can conflate multiple obligations. A native missed marker can mean no matching transaction posted, not proven nonpayment. Keep due date, expected cash date and actual settlement distinct; adapt native representation only with known effects. |
| [Moving funds in/out of goals](https://help.monarch.com/hc/en-us/articles/46420712538260-Moving-Funds-In-and-Out-of-Goals), updated 2026-08-12 | Goal-linked expenses do not enter monthly budget actuals; they remain economic purchases. Credit-card goal spending needs a funding account and native reconciliation against a covering transfer/payment. Goal adjustments differ from contributions. Refund treatment can require splitting/unlinking the original expense; read the current procedure before changing it. Native goal allocation does not execute a bank transfer. |
| [Shared Views](https://help.monarch.com/hc/en-us/articles/42228648365076-Shared-Views-in-Monarch), updated 2026-09-16 | Account/transaction owners enable filters and rules, but the household shares one budget. Ownership is not a private-account access control. Separate owner, allocated cost share and review responsibility. Native owner filters do not establish proportional household cost allocations. |

For budget mode, rollover/group behavior, category/rule ordering or a provider-specific recovery not detailed above, open the relevant official help article and inspect actual settings before proposing changes. Do not extrapolate financial effects from labels. Native receipt forwarding, invitations and support contact send information outside the current task and require explicit authorization; a read-only receipt search is a different operation.
