# Acquire source evidence

Use for a requested statement/export or an evidence gap in any Along workflow. Read [authentication](authentication.md) before live source access and [records](records.md) before saving. A source login does not change feed responsibility. Return the evidence bundle directly when acquisition is the user's goal; do not force reconciliation.

1. Resolve selected household/account identity, period and requested data. Reuse the verified connection route or user-supplied files; use account connection mode only for a genuinely missing/mismatched identity or mapping. Before live retrieval, verify the displayed source owner and selected account against a connection profile or record that verification in a same-run connection checkpoint. A shared session alone is insufficient. Label acquisition method and distinguish source account from its app representation.
2. Inspect existing manifests. Reuse intact files whose identity, actual coverage and freshness meet this request; acquire only gaps or revised versions. Preserve overlaps and older versions. An indexed file is not proof of completeness.
3. Prefer native structured exports for rows and original closed statements for statement balances. Use page tables, then screenshots/OCR as needed, preserving originals and extraction uncertainty. Payment history alone is not a complete loan principal/interest ledger.
4. Follow in-scope pages/filters/downloads and distinguish four coverage facts: the **requested interval**, the source's **declared interval** from statement/export metadata, the **observed transaction row date span**, and **validated completeness** based on source metadata and a completeness assertion. The earliest/latest transaction dates are not statement/export coverage: rows dated September 10–20 inside a requested September 1–30 interval do not show that the source covered only September 10–20 or that September 1–9 and September 21–30 are gaps. Require supplied/export metadata plus evidence that all pages/rows or the selected filter/export is complete; without that, mark the declared interval or completeness unknown/partial and do not infer coverage or gaps from no rows. Record timezone, posted/pending coverage, opening/closing balance definitions and as-of times, row counts, export limits and known gaps. Read adjacent dates or earlier baseline only when necessary to resolve the requested comparison, labeled as context.
5. Normalize only when the requested comparison/allocation needs it; a raw statement-download request can finish without parsing every row. Save a versioned derived parse with input hashes/method, source IDs or fingerprint/duplicate ordinals, integer minor units/currency exponent, original dates/descriptions and row/page provenance. Keep pending replacements and split parent/children distinct. Validate uncertain extractions against raw source; retain unresolved values and their failed checks instead of guessing.
6. Check identity, the four coverage facts, available counts/totals and comparable balance equations. Save raw files and hashes, manifest, summary and performed verification before updating the index. Hand off the manifest path, identities, declared and observed intervals, validated completeness, balance definitions and unresolved values.

Completion is **evidence acquisition** for the named scope, not app reconciliation. Missing opening balance can block an opening-to-closing proof without blocking independent row matching. Receipts support purchase allocation but do not replace institution posted ledgers. A complete acquisition does not confer write permission. Before reconciliation or a financial write consumes derived rows, validate the needed identity, amount/sign, currency and dates against source evidence; unresolved fields block the dependent conclusion or write while independent comparisons may continue.
